## Задание 1 Резервное копирование

### 1.1 Необходимо восстанавливать данные в полном объёме за предыдущий день
Для такой задачи подойдёт полное резервное копирование (Full Backup), которое выполняется, например, один раз в сутки ночью.

Суть в том, что создаётся полная копия всей базы данных.
Если произойдёт сбой, можно будет восстановить состояние базы на момент последнего резервного копирования — то есть за предыдущий день.

Также на практике часто используют схему:
-раз в сутки — полная резервная копия;
-между ними — инкрементные или дифференциальные копии.

Это уменьшает нагрузку на сервер и экономит место.

### 1.2. Необходимо восстанавливать данные за час до предполагаемой поломки

В этом случае обычной полной копии уже недостаточно, потому что можно потерять изменения за день.

Подходит:
-инкрементное резервное копирование;
-либо механизм журналирования транзакций (WAL в PostgreSQL, binlog в MySQL).

Такой подход позволяет восстановить базу практически на конкретный момент времени (Point-in-Time Recovery).

Например:
-полная копия создаётся ночью;
-журналы транзакций сохраняются постоянно;
-при сбое можно восстановить состояние базы, например, на 13:00 — за час до аварии.

Это используется в системах, где потеря даже небольшого количества данных критична.

## Задание 2 PostgreSQL

### Пример резервного копирования базы PostgreSQL (pg_dump)
```
pg_dump -U postgres -F c mydatabase > backup.dump
```
Где:
-U postgres — пользователь БД;
-F c — формат custom;
mydatabase — имя базы;
backup.dump — файл резервной копии.

Пример восстановления базы PostgreSQL (pg_restore)
```
pg_restore -U postgres -d mydatabase backup.dump
```
Где:
-d mydatabase — база, в которую выполняется восстановление;
backup.dump — файл резервной копии.

## Задание 3. MySQL

### Пример инкрементного резервного копирования MySQL

В MySQL для инкрементного резервного копирования обычно используют binary logs (binlog).
Пример включения binlog в конфигурации MySQL:
```
[mysqld]
log-bin=mysql-bin
```
После этого можно сохранять изменения через бинарные логи.

Пример команды для создания полной резервной копии:
```
mysqldump -u root -p mydatabase > full_backup.sql
```
А для восстановления изменений используют binlog:
```
mysqlbinlog mysql-bin.000001 | mysql -u root -p
```
Такой способ позволяет восстановить изменения, которые произошли после полного резервного копирования.
